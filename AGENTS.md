# AGENTS.md

Guidance for AI coding agents (Claude Code and similar) working in this
repository.

## What this repository is

A pnpm monorepo that publishes two npm packages: `@pawnary/oxfmt-config` and
`@pawnary/oxlint-config`, shared Oxfmt/Oxlint configurations for Pawnary
projects. See [README.md](README.md) for the full picture and
[CONTRIBUTING.md](CONTRIBUTING.md) for the human-facing contribution workflow.

## Setup

```sh
pnpm install
```

Requires pnpm (see `devEngines` in `package.json`; Corepack fetches it
automatically via `onFail: download`).

## Commands

| Command                       | Purpose                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `pnpm build`                  | Build every package (tsdown: ESM + CJS + `.d.ts`, regenerates each package's `exports` map, runs `publint`). |
| `pnpm lint` / `pnpm lint:fix` | Oxlint, using this repo's own `@pawnary/oxlint-config`.                                                      |
| `pnpm fmt` / `pnpm fmt:fix`   | Oxfmt, using this repo's own `@pawnary/oxfmt-config`.                                                        |
| `pnpm test`                   | Vitest.                                                                                                      |
| `pnpm changeset`              | Record a changeset for a pending change (required for any change under `packages/*/src`).                    |

Run `pnpm lint`, `pnpm fmt`, and `pnpm build` before considering a change to
`packages/*/src` complete.

## Repository layout

```
.
├── oxfmt.config.ts        # Root Oxfmt config, uses @pawnary/oxfmt-config's defineConfig
├── oxlint.config.ts       # Root Oxlint config, extends @pawnary/oxlint-config
├── tsdown.config.ts       # Shared build config for every package (workspace: true)
├── packages/
│   ├── oxfmt-config/src/  # @pawnary/oxfmt-config source (defaultConfig, defineConfig, types)
│   └── oxlint-config/src/ # @pawnary/oxlint-config source (default config object, types)
└── pnpm-workspace.yaml    # Workspace globs + shared dependency version catalog
```

## Conventions specific to this repo

- **Source of truth is `src/`.** Packages are built with tsdown into `dist/`
  (gitignored, dual ESM/CJS + declaration files). Never hand-edit anything under
  `dist/`.
- **Never hand-edit a package's `exports`/`main`/`module`/`types` fields in
  `package.json`.** They're generated by tsdown (`exports: true` +
  `@pawnary/tsdown-fix-exports`) on every `pnpm build`. If they look wrong or
  stale, run `pnpm build`, don't edit them by hand.
- **The root configs dogfood the packages via relative `src` imports**
  (`./packages/oxfmt-config/src/defineConfig.ts`,
  `./packages/oxlint-config/src/index.ts`), not via the published package names
  — that's intentional, not a bug to "fix" into a package-name import.
- **File naming is `camelCase`**, enforced by `unicorn/filename-case` in the
  repo's own lint config.
- **`oxfmt` has no native `extends`/config-composition mechanism**; that's why
  `@pawnary/oxfmt-config` exposes a merge-based `defineConfig()` helper instead
  of an `extends` array like `@pawnary/oxlint-config` does. Don't try to add an
  `extends` field to an Oxfmt config — Oxfmt won't do anything with it.
- **A consuming config's `plugins` field is merged with what `extends` pulls in,
  not replaced** — verified empirically with `oxlint --print-config`.
  `extends: [pawnary]` plus a sibling `plugins: ['react']` results in
  `['react', 'unicorn', 'typescript', 'oxc', 'import', 'vitest']`, not just
  `['react']`.
- **Tests live in `packages/<pkg>/__tests__/*.spec.ts`**, per
  `vitest.config.ts`'s `include` glob (`./packages/**/__tests__/**/*.spec.ts`) —
  not colocated `*.test.ts` files next to source. See
  `packages/oxfmt-config/__tests__/defineConfig.spec.ts` and
  `packages/oxlint-config/__tests__/index.spec.ts` for the existing pattern.
- **Some behavior can only be tested by running the real `oxlint`/`oxfmt`
  binaries, not pure JS.** For example, `@pawnary/oxlint-config`'s `extends`
  merge behavior lives in Oxlint's native Rust core — the `oxlint` npm package's
  only runtime export is an identity `defineConfig()`, so there's no JS-level
  API to assert against. `packages/oxlint-config/__tests__/index.spec.ts` shells
  out to the real `oxlint` binary with `--print-config` (via
  `node:child_process`) against a fixture config under `__tests__/fixtures/` and
  asserts on the resolved JSON output. Prefer this pattern over reaching into
  `oxlint`'s unexported internals (e.g. `dist/bindings.js`), which aren't part
  of its public API and can change without notice.

## Releasing

Any change to `packages/*/src` that consumers should know about needs a
changeset: run `pnpm changeset`, pick the affected package(s) and a semver bump,
and commit the generated file under `.changeset/` with the change. See
[CONTRIBUTING.md](CONTRIBUTING.md#releasing) for the full flow — agents should
create the changeset but should not run `pnpm changeset:version` or
`pnpm changeset:publish` (those bump versions and publish to npm, and are a
maintainer/CI action).
